Reproduce it yourself.

Every number above came from these commands, run against a throwaway vault.

# build a scratch vault + index
VAULT_ROOT=/tmp/demo-vault PORTAL_DB_PATH=/tmp/demo.db node reindex-vault.mjs

# with Dori Mini
VAULT_ROOT=/tmp/demo-vault VAULT_INDEX_DB=/tmp/demo.db \
  node query-vault.mjs last-meeting --person "Priya Menon" --sections decisions,actions
VAULT_ROOT=/tmp/demo-vault node list-tasks.mjs open
node route-destination.mjs document acme-nonprofit

# without Dori Mini — the naive fallback
grep -rli "priya menon" /tmp/demo-vault/projects | xargs cat | wc -c

# the 6-document needle-in-haystack search
VAULT_ROOT=/tmp/docs-vault VAULT_VECTORS_DB=/tmp/docs.db node semantic-index.mjs index
VAULT_ROOT=/tmp/docs-vault VAULT_VECTORS_DB=/tmp/docs.db \
  node semantic-index.mjs search "what do we lose cancelling the venue 5 days out" 2

# the PDF number, through the real markitdown pipeline
markitdown my-resume.pdf >> pdf-vault/references/clippings/resume.md
VAULT_ROOT=/tmp/pdf-vault VAULT_VECTORS_DB=/tmp/pdf.db node semantic-index.mjs index
VAULT_ROOT=/tmp/pdf-vault VAULT_VECTORS_DB=/tmp/pdf.db \
  node semantic-index.mjs search "what share of company revenue came from the GPS products he led" 2

What this doesn't claim.

The limits of the table above, stated plainly.

A small test vault

12 files, one project. The gap only widens as a real vault accumulates months of history — grep's cost grows with matches; the store-backed lookups don't.

One search example, not an average

The keyword-vs-semantic row is one real regex miss. Treat it as illustrative of a known failure mode, not a universal 3× figure.

Not every case has a number

Summarizing, disambiguating and extracting minutes spend real model tokens either way. That side is covered under what it costs to run.

Four things have no "without" column

The watched folder, WhatsApp capture, receipt photos and daily update checks need a process that outlives the conversation. They aren't faster without Dori Mini — they don't exist.

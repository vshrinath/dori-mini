Reproduce it yourself.

Against your own vault, not ours. The "without" side is the by-hand baseline — every real meeting-type file, read in full.

# the by-hand baseline: every real meeting-type file, in full
find "$VAULT_ROOT" -name '*.md' \( -iname '*mom*' -o -path '*/meetings/*' \) \
  | tee /dev/stderr | xargs cat | wc -c

# the same two questions, through Dori Mini
node query-vault.mjs last-meeting --person "Priya Menon" --sections decisions,actions | wc -c
node list-tasks.mjs open | wc -c

# routing — deterministic, no model call
node route-destination.mjs document orbitpay

# the PDF needle, through the real markitdown pipeline
markitdown resume.pdf >> "$VAULT_ROOT/references/clippings/resume.md"
node semantic-index.mjs index
node semantic-index.mjs search "what share of company revenue came from the GPS products he led" 2

Does the structure reduce hallucination?

One eval, on a real transcript rather than a written-for-the-test one.

A real 973-line meeting transcript — actual speech-to-text output, with all the noise that implies. A ten-question answer key was fixed before either answer was generated, and four of the ten were chosen precisely because the source itself hedges or contradicts: a speaker says "Monday, Monday or Tuesday"; another says a task is done "if he has completed" it; a third names the speaker as "either Hari or Gautam".

A bare "summarize this meeting" prompt scored 6 of 10. The structured extraction Dori Mini actually uses scored 10 of 10. Every miss had the same shape: a hedge in the source flattened into false confidence — "tomorrow" where the speaker contradicted himself, one name picked where the transcript named two.

Honestly: this is one transcript, and the grading was not blind. It is a real signal about a specific, repeatable failure mode — a summarizer with nothing telling it to flag uncertainty will invent certainty — and not a measured hallucination rate. Don't quote it as one.

Where it breaks.

Run specifically to find failure modes. This one is real and unfixed.

Paraphrase brittleness. Semantic search finds a fact reliably when your wording is close to the source's. Ask the same thing in natural, generic language and it can miss entirely. Against the real vault, for a standup time stated plainly in one file:

How you askCorrect file in the top 5?
"we have a stand-up at 2.30" near-exact wordingYestied for rank 1
"what time is the Pulse team's daily stand-up" natural phrasingNofive wrong files, all real, none containing the answer
"when does the team meet each day to sync on progress" generic paraphraseNofive wrong files, and the wrong project entirely

The same pattern held on a second, independent fact. Some paraphrases work and some genuinely fail, and there is no way to tell which from the outside without checking the chunk. An earlier round of tests claimed a 3× recall win for paraphrased search on a small synthetic vault; this result is why that claim has been withdrawn rather than repeated.

What this doesn't claim.

The limits of the table above, stated plainly.

One vault, one person's working habits

About 2,800 files accumulated by real use. A vault shaped differently — fewer meetings, more documents — will not produce these exact ratios.

The retrieval wins are not universal

See "where it breaks" above. When the paraphrase misses, the saving is zero and you get a wrong-looking answer instead.

Not every case has a number

Summarizing, disambiguating and extracting minutes spend real model tokens either way. That side is covered under what it costs to run.

Four things have no "without" column

The watched folder, WhatsApp capture, receipt photos and daily update checks need a process that outlives the conversation. They aren't faster without Dori Mini — they don't exist.

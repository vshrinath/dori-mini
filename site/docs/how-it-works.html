How it works

One line, run once.
Nothing hidden.

What the install does to your machine, what it leaves behind, and what it costs to keep running.

1 · What the install does.

Every question it asks, and every one you can skip.

$ curl -fsSL https://mini.mydori.app/install.sh | sh

✓ Node.js 24 found (installs it automatically if missing)
✓ npm dependencies installed (local search model, one-time)
✓ yt-dlp found (installs it automatically if missing)
✓ markitdown found (installs it automatically if missing)
? Path to your vault: [Enter = creates one for you]
✓ vault skeleton created
? Your name: (required — for meeting-attendee matching)
? Fathom API key (optional): [Enter to skip]
? Tavily API key (optional): [Enter to skip]
✓ wired into Claude Code
? Set up the WhatsApp channel? [y/N] (macOS only, optional)
? Set up a watched inbox folder? [y/N] (macOS only, optional)
? Set up morning/evening digests? [y/N] (macOS only, optional)
? Check for updates once a day automatically? [y/N] (macOS only, optional)
  • The one real download is a local search model — a few hundred MB, once. It runs entirely on your machine, and it's what makes "find that thing I was thinking about" work later even when your wording doesn't match. Everything else is standard open-source npm libraries.
  • Your vault is the only thing that matters — press Enter and it creates one for you. Everything else is disposable and rebuilds from that folder.
  • The two optional keys — Fathom pulls meeting recordings straight from your account instead of you pasting a transcript; Tavily looks up context on a new meeting attendee or contact. Skip both if you don't have them.
  • Wiring into your agent is the only thing it touches outside its own folder — Claude Code, Codex CLI, Antigravity, or Grok Build, whichever you already have. That agent is also the entire interface: there is no separate app or website to learn.
  • Every macOS prompt can be a no — WhatsApp channel, watched folder, digests, daily update check. Say no to all four and set any up later. The WhatsApp one runs on Baileys, an unofficial but widely used library for connecting your own account as a channel — not something built or run by WhatsApp itself. 2 · What it leaves behind.

Five empty folders at first, filling in only as you use it. By default at ~/dori-vault — open it in Finder or Explorer any time. It isn't a database that needs this tool to read it.

Every folder on the right came from something you said in chat — nothing was scaffolded in advance. The one exception is inbox/, which is there from the start and is where anything ambiguous lands instead of being filed wrong.

A .md file is plain text with a few light symbols for structure — # for a heading, - for a bullet. It opens in any text editor and pastes into Word or Google Docs with formatting intact. It's used here because it's the cheapest format for an agent to read: no parsing, no proprietary structure, just words.

3 · What it costs to run.

The naive way to build this would send every routing decision, every search and every "where does this go?" to a language model. This is built the other way around — the model is called only where judgment genuinely can't be avoided.

LayerModel cost
SQLite + FTS5 full-text indexEvery vault file is indexed into a local node:sqlite database the moment it's written. Exact and near-exact recall is a plain SQL query. none
Local embedding modelFor a paraphrased question, a small model (all-MiniLM-L6-v2, via Transformers.js) runs on your machine to compare meaning. No API key, no network call. none
Hybrid search, fused by formulaKeyword and vector results are merged with reciprocal rank fusion (k=60). The re-ranking step is arithmetic, not an inference call. none
Deterministic routing"Is this an expense?", "which category?", "does this belong to an existing project?" — plain code and folder-matching rules, not a model guessing afresh each time. none
Two-tier handling of long transcriptsA transcript over roughly 1,500 tokens is compressed by a small fast model first — filler cut, every decision, number and action item kept verbatim — before the main model extracts anything. small model, past the threshold
No server, no hosted backendEvery piece above is a script your agent runs on your machine. Nothing meters requests. The only spend is the agent subscription you already have. none

4 · What it's built on.

Every piece is a widely used, inspectable open-source project. None of it is controlled by this one.

  • Node.js — node:sqlite and node:crypto run the index and local database. No separate database server to install. github.com/nodejs/node →
  • Transformers.js — Hugging Face's JavaScript port, running the embedding model entirely on your machine. github.com/huggingface/transformers.js →
  • Xenova/all-MiniLM-L6-v2 — the embedding weights themselves, loaded once and cached locally. huggingface.co →
  • yt-dlp — pulls YouTube captions and the uploader's own chapter markers. github.com/yt-dlp/yt-dlp →
  • markitdown — Microsoft's converter, turning PDF, DOCX, PPTX and XLSX into clean Markdown locally. It reads embedded text, so a scanned image-only PDF won't extract this way — a photographed receipt is read by the multimodal model instead, which is why that one path costs a few tokens. github.com/microsoft/markitdown →

5 · Leaving, and staying current.

  • No lock-in. Delete this tool entirely and your vault — every transcript, every minutes doc, every ledger row — is still a folder of Markdown files on your own disk. Nothing is locked into a format only this can read.
  • Updates. The install line only handles a fresh install. On a machine that's already set up, run ./update.sh from wherever it lives (~/.claude/skills/dori by default). It refuses to run over uncommitted local changes rather than overwriting them, and only reinstalls dependencies if one actually changed. Say yes to the optional install prompt (macOS) and it checks daily on its own — you're notified only when something changed or it's blocked and needs you, never on the common no-op day.
